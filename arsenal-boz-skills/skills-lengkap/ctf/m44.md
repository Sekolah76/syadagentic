## TRIAGE (wajib)
```bash
file ./chal && checksec ./chal      # RELRO, Canary, NX, PIE, libc?
strings ./chal | grep -iE "flag|/bin/sh|system|win"
nm -C ./chal 2>/dev/null | grep -iE "win|backdoor|shell"   # ret2win?
```
Decision tree dari checksec:
- No canary + NX + ada `win()` → **ret2win** (paling simpel).
- No canary + NX, no win, libc dikasih → leak libc, **ret2libc / one_gadget**.
- PIE on → butuh address leak dulu (format string / partial overwrite).
- Menu malloc/free berat → **heap track**.

Offset: `cyclic 200` → crash → `cyclic -l <value>`.

## EXPLOIT TRACKS
- **ret2win** — overflow ke saved RIP → addr `win()`. Jaga alignment (tambah `ret` gadget kalau `movaps` segfault).
- **ret2libc** — leak GOT via puts/printf → id libc (libc-database) → hitung `system`/`/bin/sh` → ROP. Atau `one_gadget`.
- **format string** — `%n` write ke GOT, `%N$p` leak. pwntools `fmtstr_payload(offset, {addr:value})`.
- **heap** — tcache poisoning, double-free, fastbin dup, unsorted-bin leak; `__free_hook`/`__malloc_hook` (libc lama) atau FSOP/`_IO_2_1_stdout_` (libc baru). Catat ukuran chunk + urutan free di `findings.json`.
