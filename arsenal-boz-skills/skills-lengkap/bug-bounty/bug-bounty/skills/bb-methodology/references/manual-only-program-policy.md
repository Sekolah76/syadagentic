# Manual-Only Bug Bounty Programs

Use when a live policy prohibits automated tools, scripts, scanners, or findings sourced from public indexes/archives.

## Hard interpretation

Treat the restriction literally. Do **not** run:

- scripted certificate-transparency or passive-DNS enumeration;
- `subfinder`, `amass`, `httpx`, `katana`, `gau`, archive/index searches, port scanners, or scanner-like loops;
- Python/Bash loops that probe candidate hosts, paths, parameters, or methods;
- batch `curl` requests disguised as “manual recon.”

“Passive” does not override an explicit automation ban. If the policy separately excludes URL findings from search engines/indexes, do not use those sources to build the attack surface.

## Allowed workflow

1. Snapshot the live policy and write `SCOPE_FENCE.md`.
2. Record all explicit host, platform, technique, privacy, and disclosure exclusions.
3. Apply operator narrowing immediately, such as skipping native applications.
4. Use a normal browser and inspect one first-party page or feature at a time.
5. Follow links and requests generated by that manual interaction only.
6. Make single, hypothesis-driven HTTP experiments—not endpoint lists or permutations.
7. For authenticated authorization testing, obtain researcher-owned test accounts through the program-approved path; do not enumerate real accounts.
8. Stop on accidental customer/company data exposure, preserve minimum evidence, disclose it.
9. Report only through the exclusive program channel; do not place confidential findings in public services.

## Session planning

Choose one goal and one or two bug classes before touching the target. For a tenant SaaS product, prioritize:

- authentication/session boundaries;
- horizontal and vertical authorization;
- tenant isolation;
- sensitive-action CSRF;
- server-side URL consumers;
- exploit-capable XSS.

If no self-registration exists, unauthenticated work can map login, password-reset, account-discovery, and SSO flows. Do not claim that authenticated coverage was completed without owned accounts.

## Evidence language

Separate:

- manually observed route or request;
- hypothesis;
- single-request reproduction;
- authenticated production impact;
- blocked coverage due to missing researcher-owned roles/accounts.

Never describe automated output as manual testing.
